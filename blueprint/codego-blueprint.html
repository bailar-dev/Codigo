Sandbox təhlükəsizliyi

  • Judge0 ayrıca VM-də, şəbəkəsiz işləyir. Hər icra üçün limit: 2 s CPU, 128 MB yaddaş, 64 KB çıxış.
  • Gizli testlər heç vaxt brauzerə göndərilmir. Pyodide yalnız görünən testləri və oyun simulyasiyasını işlədir.
  • Oyun dünyası deterministik simulyatordur. Eyni simulyator serverdə Python harness kimi işləyir, nəticə serverdə yenidən təsdiqlənir və XP yalnız bundan sonra verilir. Bu, saxta XP-nin qarşısını alır.
3 · Sistem axını

Qeydiyyatdan fərdi yola qədər

A. Müəllim: materialdan Knowledge Graph-a

UploadMüəllim PDF, DOCX, PPTX və ya mətn yükləyir. Fayl S3-a yazılır, materials cədvəlində status=queued olur.
Parse və chunkWorker mətni çıxarır, 500-800 tokenlik parçalara bölür, embedding hesablayır və material_chunks-a yazır (RAG üçün).
Graph extractionClaude materialı oxuyur və JSON sxemə uyğun anlayışlar, prerequisite kənarları və həftə təqvimini qaytarır. Anlayışlar hər dil üçün kanonik taksonomiyaya bağlanır (py.loops.for), beləcə müxtəlif kursların datası müqayisə oluna bilir.
Müəllim yoxlamasıGraph review ekranında müəllim anlayışları birləşdirir, silir və ya sırasını dəyişir. Dərc olunanda course_versions-da yeni versiya yaranır. Köhnə versiyada olan şagirdlər ona bağlı qalır.
Item bank generasiyasıHər anlayış üçün gecə Batches API ilə 3 çətinlikdə lab, kvest və quiz sualları yaranır, sandbox-da yoxlanır və təsdiq növbəsinə düşür.

B. Şagird: qeydiyyat və cold-start diaqnostika

QeydiyyatSSO ilə giriş, sinif kodu ilə enrollment. Sistem şagirdi kursun cari versiyasına bağlayır.
Adaptiv test (CAT)Item bankdakı hər sual anlayış və çətinliklə (IRT parametri b) etiketlənib. Test orta çətinlikdən başlayır. Hər cavabdan sonra şagirdin bacarıq qiyməti (θ) yenilənir və növbəti sual ən çox qeyri-müəyyənlik olan anlayışdan, θ-ya ən yaxın çətinlikdə seçilir.
Dayanma qaydasıStandart xəta 0.3-dən aşağı düşəndə və ya 15 sualdan sonra test bitir. Sual növləri: kod oxuma (MCQ), Parsons (sətirləri sırala), qısa kod yazma.
İlkin mastery vektoruHər anlayış üçün başlanğıc P(L₀) yazılır. Yoxlanmayan anlayışlar prerequisite qrafı üzrə yaxın anlayışlardan təxmin olunur.

C. Path Engine: yolun qurulması və yenidən çəkilməsi

Yol müəllimin təqvimini pozmur, onun üzərində fərdiləşir. Qayda: təqvim sırası ilə get, mənimsənilmişi keç, zəif prerekvizit varsa əvvəl onu bərpa et.

def next_node(student, course):
    for concept in course.schedule_order:              # müəllimin təqvimi
        m = mastery(student, concept)
        if m >= 0.85:
            continue                                  # mənimsənilib, keç
        weak = [p for p in prereqs(concept) if mastery(student, p) < 0.6]
        if weak:
            return remedial(weak[0], misconception=open_misconception(student, weak[0]))
        return practice(concept, band=difficulty_band(m))  # asan / orta / çətin

# Hər submission-dan sonra: BKT update → misconception yoxlaması → lazım olsa path_nodes-a yeni versiya

Yenidən çəkmə tetikleyicisi: eyni misconception 7 gün ərzində 2 dəfə təsdiqlənərsə (məsələn recursion.missing_base_case), yola qırmızı remedial node əlavə olunur: 3 dəqiqəlik mikro-izah, həmin səhvi hədəfləyən 2 qısa tapşırıq və bir yoxlama sualı. Node keçiləndə misconception resolved olur.

Mastery modeli: Bayesian Knowledge Tracing

Düzgün cavab: P(L | ✓) = P(L)·(1 − S) / [ P(L)·(1 − S) + (1 − P(L))·G ]
Səhv cavab: P(L | ✗) = P(L)·S / [ P(L)·S + (1 − P(L))·(1 − G) ]
Öyrənmə: P(L)ₙₑₓₜ = P(L | obs) + (1 − P(L | obs))·T
Başlanğıc: T = 0.10, G = 0.20 (təxmin), S = 0.10 (səhv). İpucu istifadə olunubsa düzgün cavab qismən sayılır.

BKT sadədir, izah oluna bilir və az datada işləyir. Pilotdan sonra kifayət qədər data yığılanda parametrlər hər anlayış üçün öyrədilir, daha sonra Deep Knowledge Tracing sınaqdan keçirilə bilər.

E. Gamification

  • XP yalnız serverdə təsdiqlənən hərəkətlər üçün verilir və xp_ledger-ə append-only yazılır. Balans cəmdən hesablanır, ona görə audit edilə bilir.
  • Nailiyyətlər qayda mühərriki ilə yoxlanır: event (submission.passed) → kriteriya (JSON) → user_achievements.
  • Streak şagirdin saat qurşağına görə hesablanır, həftədə 1 "dondurma" günü verilir ki, motivasiya cəzaya çevrilməsin.
  • Siniflər arası liderlik cədvəli MVP-də yoxdur. Yalnız şəxsi irəliləyiş göstərilir, çünki zəif şagirdləri ruhdan salmamalıdır.
4 · Verilənlər bazası

Bir PostgreSQL, altı domen

Hər şey PostgreSQL-dədir. Strukturlu əlaqələr relational cədvəllərdə, dəyişkən məzmun (test case-lər, kvest xəritələri, AI cavabları) JSONB-də, material embedding-ləri pgvector-da saxlanılır. Redis yalnız müvəqqəti data üçündür. Analitika event-ləri əvvəl aylıq partition olunan cədvələ yazılır, böyüyəndə ClickHouse-a köçürülür.

Bu həftə başlamaq üçün

  1. Repo strukturunu yaradın və hər kəsin lokal mühitini bir əmrlə qaldırın (docker compose up).
  2. Kanonik Python anlayış taksonomiyasını yazın: təxminən 60 anlayış, prerequisite-ləri ilə (py.vars → py.cond → py.loops.for …). Bu, bütün sistemin onurğasıdır və AI-siz də hazırlanır.
  3. Misconception taksonomiyasını yazın: hər anlayış üçün 3–5 tipik səhv. Bunu bir müəllimlə birlikdə edin.
  4. Bir real sillabus götürüb Claude ilə graph extraction prototipini skript kimi yazın. UI-dan əvvəl çıxışın keyfiyyətini yoxlayın.
  5. Judge0-u qaldırıb bir Python lab üçün gizli testləri işlədin. Bu iki prototip işləyirsə, ən böyük texniki risklər bağlanıb.
  6. Pilot üçün bir IT kursu ilə indidən danışın. Sprint 1-də onların real materialı ilə işləməlisiniz.
